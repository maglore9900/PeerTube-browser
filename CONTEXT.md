# Glossary

- **Profile** — an optional per-visitor identity held by the Client backend, proved by an opaque key sent as `X-Profile-Key`. Likes kept server-side, dislikes and blocks belong to a profile.
- **Dislike** — a profile's soft negative signal on one video. The video is removed from that profile's feeds and videos similar to it are ranked lower; nothing changes for other visitors and no interaction event is published. A dislike and a like on the same video replace each other.
- **Taste vector** — one of up to four centroids the Engine computes from a profile's disliked videos' embeddings. The Client backend stores them and sends them with the profile's feed requests; the Engine penalises candidates close to them.
- **Interaction event** — a `Like`, `UndoLike` or `Comment` the Client backend publishes to the Engine's ingest bridge. Its `event_id` is the idempotency key: the Engine stores an id once and ignores it on every later arrival. The id is derived, never random, so a replay collapses and a genuine new like does not (ADR-0001). The Engine keeps each raw event's id for good; the event's payload and actor are stripped after the retention window (ADR-0005).
- **Interaction signal** — the Engine's per-video aggregate of ingested interaction events (`interaction_signals.signal_score`), stored uncapped. No feed order and no returned row reads it: the global orders rank on the source instance's counts only (ADR-0001, amended).
- **Published like** — a profile's like of one video that has reached the Engine. The Client backend tracks it in `like_generations` with a like generation, which goes into the event id. Opening a new published like advances the generation. Closing it keeps the generation; an un-like or a dislike replacing the like closes it. A `Like` is published only when a published like opens, and an `UndoLike` only when one closes. It is independent of the profile's likes list: a reset or the `max_likes` trim leaves it open, an imported like never opens one, and deleting the profile removes it (ADR-0001).
- **Client address** — the address of the visitor behind a request, as the Client backend resolves it: the last `X-Forwarded-For` hop when the TCP peer is a trusted proxy (`TRUSTED_PROXIES`, default loopback), the TCP peer otherwise. It keys every rate limiter and reaches the Engine as `X-Client-IP` (ADR-0002).
- **ANN id** — the id an embedded video carries in the FAISS index and the random cache: `video_embeddings.ann_id`, a 63-bit hash of `video_id` and the normalised `instance_domain`. It is derived from the video's identity, so it survives merges, purges and reloads, unlike the SQLite rowid it replaces (ADR-0006).
- **Block** — a profile's hard exclusion of a channel (`instance_domain` + `channel_id`) or an account (`account_url`) from its feeds and search results. Distinct from a dislike, which removes one video and down-ranks similar ones, from the Engine's operator moderation, which applies to every visitor, and from the NSFW filter, which is a browser setting and needs no profile.
- **NSFW filter** — a per-browser setting, on by default, that makes the Engine leave videos flagged `videos.nsfw = 1` out of every video listing: the home feed modes, up-next and search. It is kept in the browser's `localStorage`, never on the profile, so it does not follow a profile key. A visitor turns it off by sending the exact query value `nsfw=1`; any other value, or none, means filtered. Videos with an unknown flag (NULL) pass. It is distinct from a block, a dislike and operator moderation, and a video page opened directly is never filtered (ADR-0007).
- **Feed mode** — the visitor's choice of home feed: recommendations (the default), hot, recent, random or popular. It travels as the `mode` query parameter and applies only to unseeded requests. It is distinct from the Engine's profile mode (`home`/`upnext`, reported as `seed.mode`), which it never sets.
- **Hot** — the feed mode that serves the age-decayed popular ordering (`popularity`, then crawled likes and views) as one global order, the same for every visitor.
- **Popular** — the feed mode ordered by all-time crawled likes, then views, as one global order. It has no age decay. Distinct from the recommendation mix's popular layer, which uses the Hot order.
